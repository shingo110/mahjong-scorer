P1 · 严重问题

P11. Service Worker cache-first 导致新版本永远无法触达老用户

位置public/sw.js 第 17–30 行
问题fetch handler 采用 cache-first：先 caches.match 命中即返回，未命中才 fetch 并 cache.put。install 阶段已预缓存 '/'。静态导出 + trailingSlash 下，'/' 命中预缓存的旧 index.html → 引用旧 JS chunk → 旧 chunk 同样命中缓存 → 用户永远停留在首次访问时的版本。即便服务端已部署新版，老用户拿不到更新，除非手动清缓存或卸载重装。
影响对一个持续迭代的 PWA 是阻断性缺陷：发版后修复无法下发，bug 修复与新功能对老用户永久不可见。
展开：现状代码与修复方案 
// ❌ 现状：纯 cache-first，无版本治理
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then((cached) => {
      return cached || fetch(event.request).then((response) => {
        return caches.open(CACHE).then((cache) => {
          cache.put(event.request, response.clone());
          return response;
        });
      });
    })
  );
});
// ✅ 修复：导航请求 network-first（保证拿到最新 HTML），静态资源 stale-while-revalidate
// + activate 阶段清理旧版本缓存
const CACHE = 'mahjong-scorer-v2';
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) =>
      Promise.all(keys.filter(k => k !== CACHE).map(k => caches.delete(k)))
    )
  );
  self.clients.claim();
});
self.addEventListener('fetch', (event) => {
  const req = event.request;
  if (req.method !== 'GET') return;
  const url = new URL(req.url);
  if (url.origin !== location.origin) return; // 仅缓存同源
  // HTML 导航：网络优先，失败回退缓存
  if (req.mode === 'navigate' || req.destination === 'document') {
    event.respondWith(
      fetch(req).then((res) => {
        const copy = res.clone();
        caches.open(CACHE).then((c) => c.put(req, copy));
        return res;
      }).catch(() => caches.match(req).then((r) => r || caches.match('/')))
    );
    return;
  }
  // 其他静态资源：stale-while-revalidate
  event.respondWith(
    caches.match(req).then((cached) => {
      const network = fetch(req).then((res) => {
        caches.open(CACHE).then((c) => c.put(req, res.clone()));
        return res;
      }).catch(() => cached);
      return cached || network;
    })
  );
});

注意：修改 SW 后务必 bump CACHE 版本号，否则旧 SW 不会重新激活。

P12. 游戏状态仅存内存，刷新/切后台即丢失全部记分

位置src/lib/game-context.tsx 第 108 行 useReducer(gameReducer, initialState)
问题players / score / history 全部只存在于 React state，无任何持久化。src/lib/utils/app.ts 里已写好完整的 storage 工具（saveRoom/getRoomData 等）却从未接入。后果：
  • 记分到一半误刷新页面 → 数据全丢，回到 setup 首页
  • 手机切后台被系统回收进程 → 重进丢失
  • 直接访问/刷新 /game、/history、/settlement 子路由 → Context 重置为 initialState，players.length===0 触发 router.replace('/') 或显示"暂无数据"
影响对一个"记分"工具，数据丢失即核心功能受损。尤其线下麻将一局可能持续数小时，中途丢分体验灾难。
展开：修复方案 
// ✅ reducer 懒初始化从 localStorage 读取，每次变更后持久化
const STORAGE_KEY = 'mahjong-game-state';

function lazyInit(): GameState {
  if (typeof window === 'undefined') return initialState;
  try {
    const raw = localStorage.getItem(STORAGE_KEY);
    if (raw) return { ...initialState, ...JSON.parse(raw) };
  } catch { /* ignore */ }
  return initialState;
}

const [state, dispatch] = useReducer(gameReducer, undefined, lazyInit);

useEffect(() => {
  try { localStorage.setItem(STORAGE_KEY, JSON.stringify(state)); } catch {}
}, [state]);

注意 reset 时也要 localStorage.removeItem；settlement 完成后可选地归档历史局到独立 key。

P13. 死代码与死依赖：未完成的"多人联机"残留

位置src/lib/utils/app.ts、src/lib/types.ts（Room）、package.json
问题全局搜索确认以下内容在整个 src 中零调用方，仅为内部自引用：
  • 依赖 socket.io-client（^4.8.3）—— src 无任何 import，纯死依赖
  • 依赖 uuid（^14.0.0）—— 仅被 getDeviceId() 使用，而 getDeviceId 本身无人调用
  • 函数：generateRoomId()、getDeviceId()
  • 对象：storage 全部方法（saveRoom / getCurrentRoom / clearRoom / saveRoomData / getRoomData）
  • 类型：Room（types.ts）
影响① socket.io-client 约 40KB+ 无谓进入 bundle（若被 tree-shake 掉则仅 lock 文件污染，但仍误导）；② 扩大供应链攻击面；③ 与实际"纯本地单机"架构矛盾，严重误导后续维护者以为存在联机能力；④ uuid 只为生成 deviceId，可用 crypto.randomUUID() 替代（浏览器原生）。
修复删除上述死代码；从 package.json 移除 socket.io-client 与 uuid，重新 npm install。若未来要做联机，再按需引入。

P2 · 重要问题

P24. 字体变量断裂：Geist 字体从未生效，全站回退系统字体

位置src/app/globals.css 第 10–12 行；src/app/layout.tsx 第 8–11 行
问题layout 中 Geist({ variable: "--font-geist-sans" }) 定义的是 --font-geist-sans，但 globals.css 的 @theme inline 块里写的是自引用：
--font-sans: var(--font-sans);      /* ❌ 自引用，无意义 */
--font-mono: var(--font-geist-mono); /* ✅ 正确 */
--font-heading: var(--font-sans);    /* ❌ 指向断裂的 --font-sans */
影响html 上虽挂了 geist 的 variable class，但 font-sans / font-heading 工具类拿不到 Geist，全站（含 @apply font-sans）回退到系统字体。设计意图（Geist 无衬线）完全未实现。
修复改为 --font-sans: var(--font-geist-sans); 与 --font-heading: var(--font-geist-sans);

P25. 主题切换白屏闪烁（FOUC），无防闪脚本

位置src/components/theme-toggle.tsx 第 46–57 行（applyTheme 在 useEffect 中调用）；src/app/layout.tsx
问题预渲染 HTML（见 out/index.html）的 <html> 无 data-theme 也无 .dark，即默认 light。若用户本地存了 dark / 自定义暗色主题，需等 React hydration + useEffect 执行后才切换 .dark。首屏先白后黑，每次打开都闪烁。无内联 head 脚本提前设置主题。
修复在 layout 的 <head> 注入一段同步内联脚本，在 React hydrate 前读取 localStorage['mahjong-theme'] 并设置 document.documentElement 的 data-theme 与 .dark class。

P26. 主题悬浮球：拖动定位后误触发 click 开关面板

位置src/components/theme-toggle.tsx 第 168–178 行（同一 button 同时挂 onClick 与 onPointerDown/Move/Up）
问题pointerdown 置 dragging=true，pointerup 置 false，但浏览器在 pointerup 后仍会派发 click。即使用户发生了明显拖动位移，松手时仍触发 setOpen(v => !v)，导致拖动后面板被意外打开或关闭，行为不可预测。代码未用位移阈值抑制 click。
修复在 pointerdown 记录起始坐标，pointerup 计算位移；若位移超过阈值（如 5px）则标记 movedRef，在 onClick 中若 movedRef 为真则忽略并重置。

P27. 结算后仍可返回记分页继续改分，状态机不闭环

位置src/app/settlement/page.tsx 第 131–135 行（"返回记分" router.push('/game')）；src/lib/game-context.tsx SETTLE 只改 phase
问题settle() 仅把 phase 置为 'settlement'，但 game 页不检查 phase，结算后点"返回记分"仍可正常加减分、再结算。phase 状态机形同虚设，结算结果与后续操作语义混乱。
修复game 页在 phase !== 'playing' 时禁用 NumberPad 或引导回结算页；或结算后锁定计分入口。

P28. Service Worker 无缓存清理 + 无白名单，缓存无限增长

位置public/sw.js
问题① 无 activate 阶段删除旧版本缓存，CACHE 固定 'mahjong-scorer-v1'，改版后旧缓存永不释放；② cache.put(event.request) 缓存所有成功响应，无同源白名单，跨域请求、未来引入的第三方资源都会被缓存，长期使用存储膨胀。
修复见 P1-1 修复方案中的 activate 清理与同源白名单。

P29. lint 脚本失效，质量门禁形同虚设

位置package.json 第 9 行 "lint": "eslint"（无参数）
问题npm run lint 报 'eslint' 不是内部或外部命令（git bash 下 PATH 注入异常）。即便修复 PATH，ESLint 9 flat config 下 eslint 不带路径行为不明确。本地用 ./node_modules/.bin/eslint . 可跑且零警告——但这恰恰说明配置宽松：未开 @typescript-eslint/no-unused-vars，故 P1-3 的死代码无法被 lint 拦截。另：node_modules/.bin/tsc 缺失，无法独立做类型检查，只能依赖 next build。
修复脚本改为 "lint": "eslint ."；按需开启 no-unused-vars（warn）拦截死代码；确保 typescript 已安装以便 CI 独立 tsc --noEmit。

P310. 数字面板前导零：显示与实际值不一致

位置src/app/game/number-pad.tsx 第 17、54 行
问题input 为字符串，显示原始 input（如 "01"），但 value = parseInt("01") = 1，按 + 实际加 1。用户看到 01 却加 1，存在认知偏差。输入 "00" 时 value=0 按钮 disabled，但显示 00。
修复追加数字时去除前导零：const next = (parseInt(prev + key, 10) || 0).toString()，或直接显示归一化后的 value。

P315. 可访问性：主题色块无 aria、按钮触摸目标偏小

确认安全的方面

SAFE无 XSS / 注入风险

结论全局搜索 dangerouslySetInnerHTML / innerHTML / eval / new Function / document.write —— 无任何匹配。用户输入的昵称、金额均作为 React 文本节点渲染，自动转义。localStorage 的 JSON.parse 均有 try/catch 保护。无外部 API 调用、无密钥、无敏感数据处理。从安全角度，这是一个低风险的应用。

SAFE结算算法正确

结论calculateSettlement 采用经典贪心平账（债权人/债务人两端对冲），逻辑正确。因数字面板只输入整数，amount = Math.min 恒为整数，creditor.net === 0 的浮点比较隐患在当前数据下不成立（若未来引入小数输入需改为 Math.abs(net) < 1e-9）。
